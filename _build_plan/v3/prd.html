WaGuard v3

A template-driven WhatsApp auto-reply bot with an optional, paid AI fallback. Bots reply from assigned templates via keyword rules; when AI is switched on, off-script questions are answered from a per-bot knowledge base. Provider-pluggable (Claude default, OpenAI, Ollama), fully API-exposed, and turnkey to deploy on Cloudways.

Node.js + TypeScript Fastify 5 better-sqlite3 EJS dashboard Baileys 7 Claude / OpenAI / Ollama Docker · Cloudways (PM2 + .htaccess)

API-first & self-documenting (every milestone): Every capability ships a token-authed REST API in the same milestone that introduces it — never deferred to one "API milestone." Each endpoint lands in the OpenAPI spec (/openapi.json), /docs, and the /developers portal at the same detail as the existing v1/v2 docs (purpose, auth, payload examples, runnable console entry). A downstream app discovers what to call and how entirely from the published docs, with no out-of-band explanation.

What the app does (new in v3)

  • Create bots per number

    Build bots and bind each to linked WhatsApp numbers — one active bot per number.

  • Template menu flows

    Assign v2 templates and define keyword→template rules with a default-case fallback.

  • Auto-reply in real time

    Inbound messages answered automatically through the existing anti-ban / health / consent engine.

  • AI toggle (paid upgrade)

    Off = template-only. On = off-script questions answered from a persona + knowledge base.

  • AI Provider Hub

    Connect Claude / OpenAI / Ollama, test the connection, route models, cap monthly spend.

  • Per-bot knowledge base

    Paste text or upload docs; entries become semantically searchable for the AI fallback.

  • Full bot API + docs

    Manage bots, rules, KB, and AI config over the API; preview a reply before sending.

  • Conversation log & analytics

    Per-thread history plus KPIs: auto-resolution, rule-vs-AI share, token spend, deflection.

  • Turnkey Cloudways deploy

    A Git deploy builds and (re)starts under PM2 with little or no manual server work.

Already provided by v1 + v2

  • Single Docker container + Cloudways PM2/.htaccess deploy
  • Admin login + API tokens
  • OpenAPI docs + /developers portal & console
  • QR number linking + auto-reconnect
  • Anti-ban send queue + pacing engine
  • Inbound capture + media download
  • Signed webhooks + delivery log
  • Health monitoring + auto cool-down
  • Consent guardrails + STOP auto-block
  • Template library ({{placeholders}} + buttons)
  • Contact import, lists, broadcasts, groups
  • Analytics dashboard + branded shell/theme

Out of scope (v3) — logged as v4 backlog

  • Multi-step / stateful flows — v3 is stateless keyword routing; no memory of where a sender is in a multi-turn flow.
  • Human handoff / live-agent inbox — no in-app takeover UI (webhooks can still notify an external system).
  • AI copywriter — generating/optimizing outbound campaign copy is a separate add-on.
  • Pre-send AI compliance / spam check — flagging risky wording before a send.
  • AI translation / localization — auto-detecting and replying in the sender's language.
  • Smart send-time optimization — predicting the best window per recipient.
  • Multi-tenant / per-seat config & roles — v3 stays single-admin owner.
  • Voice / calls — text messaging only.
  • Dedicated numbered-button reply parser — the bot routes on inbound text via ordinary keyword rules.

Milestones

1

Bots & Template Rules

The template-driven bot end-to-end with no AI — the free tier. Create a bot, give it a template flow, and watch it auto-reply on the real linked number.

What gets built

  • Bots dashboard: create/edit/delete, bind to numbers (one active bot per number)
  • Rule builder: trigger→template, priority order, default-case flag
  • Bot runtime auto-sends through the anti-ban / health / consent engine
  • Per-bot + global kill switch; optional business hours; reply logging
  • Token-authed bots/rules REST API + OpenAPI/portal docs

Not in this milestone

  • Any AI, KB, persona, or provider config
  • Bot API / developer-portal docs
  • Analytics/KPI view; stateful multi-turn memory

Done when: A HELP-menu bot bound to the test number replies correctly to a matching keyword and gives the default-case reply for off-menu input, paced by the anti-ban engine.

2

AI Provider Hub

The pluggable AI provider layer and its admin surface, so later milestones can generate replies. Stands up and verifies the plumbing — nothing calls it in the bot flow yet.

What gets built

  • AI Providers screen: connect Claude/OpenAI/Ollama, DB-stored keys + .env bootstrap
  • Test-connection button with a real round-trip
  • Single AIProviderInterface abstraction; per-task model routing
  • Monthly token/cost budget + usage tally + graceful degradation
  • Provider-config REST API (no secrets returned) + docs

Not in this milestone

  • Wiring AI into the bot runtime
  • Knowledge-base ingest / embeddings storage
  • Downstream API for provider config

Done when: The admin connects Claude, clicks "test connection" and sees it succeed, sets default provider, model routing, and a monthly budget — all persisted across a restart.

3

AI Fallback (RAG)

Turn the paid AI toggle on: give each bot a knowledge base and a persona, and wire AI into the runtime so off-script input is answered from that knowledge instead of the default-case template.

What gets built

  • Per-bot Knowledge Base: paste text / upload docs → chunk + embed
  • Per-bot AI toggle, persona, and re-show-menu option
  • Runtime: off-script input → retrieve KB → grounded AI reply → optional menu
  • Graceful fallback to default-case template; AI outcomes logged with cost
  • Per-bot AI-settings + knowledge-base REST API + docs

Not in this milestone

  • Bot/KB/AI-config REST API and portal docs
  • Analytics dashboard
  • Multi-turn memory, translation, human handoff

Done when: With AI on and a small KB loaded, an off-menu free-form question returns a correct, KB-grounded answer then the menu; turning AI off makes the same question fall back to the default-case template.

4

Bot Preview & Developer-Portal Completion

The per-feature APIs already shipped with M1–M3. This milestone completes the developer experience: the preview/trigger-reply endpoint and a polished end-to-end portal walkthrough so a downstream team can self-serve with zero hand-holding.

What gets built

  • Preview/trigger-reply endpoint (rule vs AI vs default-case) without sending
  • "Build a bot" getting-started guide stitching the per-milestone endpoints
  • Audit: every v3 endpoint documented to v1/v2 quality; nothing undocumented

Not in this milestone

  • Analytics API and dashboard
  • New bot behavior / new CRUD — that shipped in M1–M3

Done when: Using only a token and the /developers portal, a developer follows the getting-started guide to create a bot, add a rule and KB entry, enable AI, and call the preview endpoint — discovering every call purely from the docs.

5

Conversation Log & Bot Analytics

Surface the Bot Reply Log as a human-readable conversation view plus KPIs, so the admin (and their clients) can see the bot working and justify the AI upgrade.

What gets built

  • Conversation Log: per-thread history with rule/AI/default-case attribution
  • KPIs: auto-resolution rate, rule-vs-AI share, token spend, deflection
  • CSV export + read-only analytics API (published in OpenAPI/portal docs)

Not in this milestone

  • Real-time streaming, custom report builder, scheduled email reports
  • Any change to bot behavior — reads existing log data

Done when: After the bot handles several messages, the admin opens the Conversation Log with correct attribution, views KPI tiles for a date range, exports a CSV, and fetches the same KPIs from the analytics API with a token.

6

Turnkey Cloudways Deploy

Make deploying to Cloudways near-zero-touch on top of the existing .htaccess / PM2 setup, so shipping updates needs little or no manual server work.

What gets built

  • Tracked config + hardened deploy: build, install, PM2 (re)start, no hand-editing
  • Idempotent v3 handling: new deps, DB migrations, AI-provider .env bootstrap
  • Updated verify/troubleshoot docs; .htaccess + PM2 survive a redeploy

Not in this milestone

  • Docker on Cloudways; changes to the local Docker workflow
  • Multi-server / autoscaling / CI beyond Cloudways Git deploy
  • Provisioning a fresh box from scratch

Done when: Pushing v3 through Cloudways Git deploy + the deploy script brings the app (bot + AI layer) up cleanly under PM2, reachable via the Application URL, migrations applied, no manual server edits.
