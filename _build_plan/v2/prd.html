WaGuard v2

Turns the working v1 service into a polished product: a redesigned, branded dashboard with an at-a-glance implementation-status overview, a first-class developer portal where downstream teams read the API contract and call it live from the panel, and the deferred functional features — contact import, templates, buttons, broadcasts, groups, and analytics — all routed through the existing anti-ban, health, and consent safeguards.

Node.js + TypeScript Fastify 5 better-sqlite3 EJS dashboard Baileys 7 Docker (single container)

What's new in v2

  • Redesigned dashboard shell

    Branded header + footer, a consistent design system, and light/dark theme across every page.

  • Implementation-status overview

    An Overview home with a live status card per capability, a health strip, and recent activity.

  • API documentation portal

    A human-friendly contract for downstream teams: getting-started, endpoints, auth, webhook payloads.

  • Interactive API console

    Call the live API from the panel with a token and see the real response — no separate tool.

  • Contact import + lists

    Upload a CSV into named lists, with column mapping, validation, and consent.

  • Template library

    Reusable templates with fill-in placeholders, optional media, and buttons.

  • Interactive buttons

    Quick-reply, call, and link buttons on messages, templates, and broadcasts.

  • Bulk / broadcast campaigns

    Send to a list under anti-ban pacing with live progress and pause/resume.

  • Group messaging

    Sync and send to the WhatsApp groups a linked number belongs to.

  • Analytics & reporting

    Date-range charts, KPI tiles, and CSV export across numbers and campaigns.

Already provided by v1 (do not re-spec)

  • Docker container + SQLite + mounted volume
  • Admin login + API-token auth
  • Auto-OpenAPI at /docs + /openapi.json
  • QR linking + reconnect
  • Anti-ban send queue + pacing engine
  • Inbound capture + media download
  • Signed webhooks + retry + log
  • Health monitoring + cool-off
  • Consent guardrails + auto-block on STOP
  • EJS dashboard shell + existing pages

Out of scope (v2) — logged as the v3 backlog

  • Auto-reply / chatbot / AI — reply logic stays in the downstream app.
  • Multi-user / team accounts & roles — v2 stays single-admin owner.
  • Adaptive / ML anti-ban auto-tuning — v2 stays rule-based, logging evidence.
  • Proxy / IP rotation — network-level anti-ban is deferred.
  • Phone-number code pairing — QR linking only.
  • Richer consent lifecycle — opt-in forms, double opt-in, expiry/import, per-number policies.
  • Live address-book sync — import is CSV-only; Google Contacts sync deferred.
  • Other interactive types — lists, polls, locations, reactions, edit/delete (buttons only in v2).
  • Advanced broadcast logic — multi-number splitting, drip sequences, send-time optimization.
  • Group administration — creating groups / managing participants (v2 only sends).
  • Streaming dashboards / report builder / scheduled email reports — analytics stays date-range + export.
  • Mobile app / extension · billing · multi-tenant SaaS — platform & business-model expansion.

Milestones

1

Design system & dashboard shell + status overview

The professional visual foundation every page renders inside, plus a live Overview home showing the state of everything already built.

What gets built

  • Cohesive design system: type, color tokens, cards, badges, buttons, tables, page headers.
  • Branded shell: header (logo, connection indicator, account/logout) + footer (version, doc/health links).
  • Refined icon left-nav across every area; persistent light/dark toggle; responsive to tablet.
  • Overview home: live status card per capability, system-health strip, quick actions, recent activity.

Not in this milestone

  • Docs portal / API console (milestone 2).
  • New functional features (import, templates, broadcasts, groups, analytics).
  • White-label theming, drag-drop widgets, phone-first redesign.

Done when: the dashboard shows the new branded header/footer and consistent design on every page, light/dark toggles, and the Overview home shows accurate live status cards, a health strip, and recent activity.

2

Developer portal: docs + interactive API console

A readable contract plus a live "try it" console — a first-class way for downstream teams to understand and consume the API, inside the branded panel.

What gets built

  • Human-friendly docs grouped by area: getting-started, endpoints, params, example request+response.
  • Webhook payloads + signature verification explained; copy-paste curl; search/filter; spec download.
  • Interactive console: pick endpoint, fill form, supply token, Send, see the real live response.

Not in this milestone

  • SDKs / code generation, versioned doc history, changelog engine.
  • Saved request collections or environment management.
  • Any new functional features.

Done when: a downstream user can open the portal, read the contract, paste a token, call a live endpoint from the console, and see the real response — without leaving the panel.

3

Contacts & content: import + lists + templates + buttons

The content and audience foundation broadcasts stand on: importable lists, reusable templates, and interactive buttons.

What gets built

  • CSV import: upload, column mapping, validation preview (invalid/duplicate flagged), target list, result summary.
  • Contact lists/segments; filter Contacts by list + consent.
  • Template library: body with {{placeholders}}, optional media, preview; pick when sending.
  • Buttons (quick-reply/call/link) on templates and the send form; placeholders filled from contact fields.

Not in this milestone

  • Broadcasts / groups (milestone 4); analytics (milestone 5).
  • Address-book sync, scheduled/auto imports, merge de-dupe beyond skip.
  • Template approval/versioning/A-B; interactive types beyond buttons.

Done when: you can import a CSV into a list, create a template with placeholders and buttons, and send a single templated message with buttons that the recipient receives.

4

Sending at scale: broadcasts + group messaging

The highest-value (and highest-risk) capability: bulk sends to a list under full anti-ban control, plus sending to existing WhatsApp groups.

What gets built

  • Create a campaign (template/inline, target list/filter, sending number, optional schedule); estimated send window.
  • Live progress (queued/sent/delivered/read/failed); pause/resume/cancel; blocked & non-consented auto-skipped.
  • Per-number daily limits + health cool-off respected.
  • Group messaging: sync groups, list them, send text/media/template via the paced queue; inbound group messages captured + webhooked.

Not in this milestone

  • Analytics dashboards (milestone 5).
  • Multi-number splitting, drip sequences, send-time optimization.
  • Group creation/administration; interactive list/poll messages.

Done when: you can launch a broadcast to an imported list and watch it progress live under pacing (pausing/resuming), and send a message to a synced WhatsApp group.

5

Analytics & reporting

Closes v2 with the reporting layer: date-range charts and KPIs across numbers and campaigns, plus export.

What gets built

  • Analytics page: date-range charts — sends over time, delivered/read/failed rates, inbound volume, per-number breakdown, campaign performance, health incidents.
  • KPI summary tiles for the selected range; CSV export.
  • A daily-stats rollup so charts load fast without recomputing all history.

Not in this milestone

  • Real-time streaming dashboards.
  • Custom/ad-hoc report builder; scheduled email reports.
  • Predictive / ML insights (v2 stays descriptive).

Done when: you can open Analytics, pick a date range, see accurate charts and KPI tiles across numbers and campaigns, and export the range to CSV.
